# Weekly Update (2026-08-03)

## Last week's prediction confirmed: contrastive extracts the pairing, prediction does not

Ran the contrastive positive control and the confound arms (8 new runs, same
pipeline/encoder/batch/steps as before — only the objective differs). Isolating
the pairing effect by comparing each mechanism against its **own shuffled-pairs**
control:

| mechanism | pairing effect (code) | pairing effect (summary) |
|---|---|---|
| JEPA (predictive) | **−.006** | **+.005** |
| Contrastive (InfoNCE) | **+.296** | **+.269** |

- The pairs **do** carry a large learnable signal — InfoNCE recovers ~.28 of it
  from scratch with only 95 in-batch negatives. Predictive JEPA recovers none.
- This makes our JEPA null **attributable to the objective**, not to our scale or
  setup: the apparatus can detect a pairing effect ~50× larger when the
  mechanism can use it. That was the main remaining reviewer attack.
- Supports the mechanism story from last week: prediction's anti-collapse term
  fights its learning signal; contrastive's *is* its learning signal.

## Confounds closed

- **Faithful LLM-JEPA (no SIGReg) is still inert** — .3464 vs the no-JEPA
  baseline .3401. Rules out "your regularizer caused the null."
- **Ordering on both corpora: no-JEPA ≥ JEPA-without-SIGReg > JEPA-with-SIGReg**
  (summary .4298 / .4184 / .3868). Cross-view adds nothing; SIGReg costs
  ~.03–.04; the remaining gap to the Part-I baseline is pipeline (batch 96 +
  paired corpus), not the objective.
- All four predictions registered *before* these runs came out confirmed,
  including the one that could have falsified the mechanism story.

Scope: contrastive is not "the better pretraining objective" (it loses to plain
MLM on summary — it has no token supervision). The claim is strictly the
**pairing effect within each mechanism**, which the shuffled controls isolate.

## DLLM-JEPA: implemented and launching

Implemented the paper's method (arXiv 2606.00091): two views of the same input
at two masking rates (.2 / .7), cosine JEPA loss against an EMA target, k-layer
predictor, on top of the standard diffusion SFT loss. Two compute adaptations
(the paper full-finetunes on 8×A100): LoRA, and an EMA teacher over the LoRA
deltas only — since the base weights are frozen and shared, this is the same
thing as a full EMA copy but costs megabytes instead of a second 16 GB model.
Also implemented our extension: the CoT as the predictor's **action** input, via
zero-init conditioning so training starts exactly as the plain reproduction.

Design point found while implementing: the reproduction and the action
experiment need **different generation targets** — the reproduction has the
model generate its CoT (as in the paper), while the action experiment uses
answer-only targets so no CoT is generated at test time. So they are run as two
separate stages, and the no-action answer-only arm (not the reproduction arm) is
the correct reference for the CoT-action arm.

First runs launching now: **Gate 1** is reproducing the published gain
(LLaDA-8B GSM8K 42.61 → 61.33) before spending compute on the action arms.
